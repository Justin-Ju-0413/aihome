## P0-1 扫描增量缓存（性能）

- **现状**：`GET /api/agents` 每次全量重扫所有工作区文件，agent 多时请求变慢（v0.2 线宽）。
- **方案**：新增 `src/lib/scan-cache.ts`。以 `(workspaceId, 文件相对路径)` 为 key、`(mtimeMs, size)` 为指纹，命中则直接返回上次 parse 结果；目录列表用 `readdir` 缓存 + 递归只进有变更的目录。写回时机：扫描完成时原子更新（先写临时文件再改名）。
- **失效场景**：文件 mtime/size 变化 → 重扫该文件；AGENTS.md/skill 目录新增/删除 → 目录级失效。
- **涉及**：`src/lib/scanner.ts`、`src/lib/parser.ts`（parse 结果可缓存化）、新增 `src/lib/scan-cache.ts`。
- **验收**：e2e——同 data 目录二次扫描命中缓存（首个请求计时，缓存命中时无 `fs.readFile` 新调用）；改文件后重扫正确反映变化。**注意**：缓存目录塞 `.aihome/scan-cache/`，不进 git；路径沙箱同上。

## P0-2 价格表扩展（provider fallback 池）

- **现状**：`src/lib/usage/pricing.ts` `BUNDLED_PRICING` 只有 9 个模型，未知模型 cost 记 0，成本面板失真。
- **方案**：三层回退 `getPricing`：
  1. `ccSwitchPricing?.[model]`（DB）
  2. `BUNDLED_PRICING[model]`
  3. **provider 前缀 fallback 池**：`claude-*` / `gpt-*` / `deepseek-*` / `glm-*` / `gemini-*` 配置行业均价兜底
  4. 全 miss → cost 按 0 计但事件带 `pricing: unknown` 标记，UI 成本面板显示"未知定价"提示而非静默 0。
  5. 允许用户配置自定义 pricing JSON 覆盖（`data/pricing-override.json`），优先级最高。
- **涉及**：`src/lib/usage/pricing.ts`、`src/lib/usage/types.ts`、前端成本面板提示。
- **验收**：pricing 单测覆盖未知模型五层优先级；e2e 面板对未知模型显示"未知定价"标记。

## P0-3 usage-cache 保留策略 + 异步化（可靠性）

- **现状**：`src/lib/usage/cache.ts` events 表只增不删，DB 无限膨胀；`indexIfStale` 同步阻塞请求路径。
- **方案**：
  - **保留策略**：默认删 90 天前事件（`DELETE FROM events WHERE ts < now-90d`），启动时 + 每轮索引后执行；常量 `USAGE_RETENTION_DAYS`，可在设置里改成 7/30/90。
  - **异步化**：索引扫描改为 fire-and-forget——先读缓存立即返回，后台 `setImmediate` 触达 reindex；响应头 `x-stale: true` 表后台正刷新；并发约束防雪崩（同一来源只跑一个后台任务）。
  - 顺手加 `ts` 单列索引（已有 `(source, ts)`），加速清理查询。
- **涉及**：`src/lib/usage/cache.ts`、`src/lib/usage/indexer.ts`、`src/lib/usage/routes`（响应头）。
- **验收**：单测覆盖清理边界（用本地时间构造过期数据）；e2e 断言 stale 响应路径 + 清理后 count 收缩。

## P1-4 接入 OpenClaw 用量源

- **现状**：`ADAPTERS` 只含 5 源；OpenClaw 预留插槽未启用。用户跑 OpenClaw 时其成本/用量不可见。
- **已侦察结论**（来自 research/openclaw-src）：
  - 每 agent 一个 SQLite：`~/.openclaw/agents/<agentId>/agent/openclaw-agent.sqlite`
  - 逐调用用量存 `cache_entries` 表（Kysely 经 `withOpenClawAgentDatabaseReadOnly` 读，只读）
  - 模型单价在共享 state DB `~/.openclaw/state/openclaw.sqlite` 的 `model_capability_cache`（含 `cost_input/cost_output/cost_cache_read/cost_cache_write`）
- **方案**：新增 `src/lib/usage/sources/openclaw.ts` 适配器：
  - `checkSourceAvailability`：找 `~/.openclaw/agents/*/*/openclaw-agent.sqlite` 列表
  - 用 `node:sqlite` 只读打开，解析 `cache_entries` → 事件（rawId/模型/token/ts，cost 先由 AIHome 定价层算；若 cache 里已存 cost 则直接用）
  - 单个 agent 目录太多时间（多 agent 逐个只读打开即可，频率低）
  - checkpoint=最新一条 `ts`
  - 配 `USAGE_SOURCE_PATHS['openclaw']` 指向 agents 根
- **涉及**：`src/lib/usage/sources/`：新增 `openclaw.ts`、`index.ts` 注册、`paths.ts` 加路径、`types.ts` 加 source。
- **风险**：OpenClaw schema 未固定为 contract，随版本可能漂——侦察据此编写的 adapter 需在 OpenClaw 版本变动发 README 字段验证（fixtures 固化当前版本字段）。
- **验收**：fixture 解析单测；无 `~/.openclaw` 时 `checkSourceAvailability` 返回 `not found` 优雅降级。
