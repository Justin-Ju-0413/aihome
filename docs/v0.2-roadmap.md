# AIHome v0.2 开发计划

> 2026-08 收口说明：v0.1.x 的稳定边界是现有 `/api/*` 成功响应结构、本地工作区扫描和看板/图谱/详情流程。以下项目按需求推进，不为了版本号强行扩大范围。

## 近期优先级

1. 首次使用引导：选择目录、预览扫描结果、校验配置后再保存。
2. 显式只读演示模式：同时禁用写入 API 和编辑控件。
3. 工作区健康面板：不可读路径、无效定义和重名项。
4. 主要平台的干净检出验证与简短可视化演示。

CLI、桌面打包、运行时执行和远程协作仅在有明确需求时启动。

---

> 现状:v0.1 是一个能跑的骨架——扫描 AGENTS.md/SKILL.md、看板+关系图+列表/详情/设置、CRUD、91 个 e2e 全绿、lint/tsc/build 干净。
> v0.2 目标:**把骨架补成真正可用的本地 Agent 工作台**——修掉半成品功能、让关系图自动反映依赖、接上文件树、数据层现代化、补文档与主题。

## 优先级总览

| 级别 | 主题 | 条目 |
|------|------|------|
| P0 | 正确性(修半成品/bug) | 布局持久化、/api/files 路径安全、关系自动检测 |

## P0 — 正确性

### 1. 看板布局持久化(修 bug)
- **问题**:`KanbanBoard.saveLayout` 把拖拽后的分组/顺序写入 `.aihome/layout.json`,但 `workspace-config.ts` 的 `getLayout()` 从未被调用;且写入格式 `{x,y,group}` 与 `getLayout` 返回的 `{x,y}` 不一致。结果:刷新页面后看板分组与顺序全部丢失。
- **范围**:
  - 统一 layout 格式为 `{ [agentId]: { group, order } }`
  - `KanbanBoard` 挂载时调 `GET /api/workspace/layout`(新端点)或复用 `/api/workspace` 返回 layout,按 layout 还原 `agent.group` 与列内顺序
  - 拖拽后写回;`saveLayout` 改用专门端点而非 `/api/files` 任意写
- **涉及**:`src/lib/workspace-config.ts`、`src/components/board/KanbanBoard.tsx`、`src/app/api/workspace/route.ts`(或新增 layout 路由)
- **工作量**:M  **验收**:拖拽改分组/顺序 → 刷新 → 保持

### 2. /api/files 路径安全
- **问题**:`/api/files` GET/PUT 接受任意 `path`,可读写进程权限内任何文件。本地工具风险有限,但一旦对外暴露即任意文件读写。
- **范围**:校验 `path` 解析后落在某个已配置工作区路径(或 agent dirPath)内,否则 403;`buildFileTree` 同理。
- **涉及**:`src/app/api/files/route.ts`、`src/lib/file-utils.ts`
- **工作量**:S  **验收**:越界路径返回 403;e2e 补用例

### 3. 关系自动检测(让关系图有用)
- **问题**:scanner 把 `dependencies`/`calledBy` 硬编码为 `[]`,关系图只能靠手动 onConnect 连线,无法反映真实依赖。
- **范围**:
  - 约定标注语法(AGENTS.md 里 `## Dependencies` / `## Calls` 章节,或 frontmatter `depends-on: [a, b]`),scanner 解析后填充 `dependencies`/`calledBy`(反向)
  - 关系图初始渲染时把这些自动关系作为边(与手连线区分样式)
- **涉及**:`src/lib/parser.ts`、`src/lib/scanner.ts`、`src/components/graph/AgentGraph.tsx`、`data/sample-agents/*`(补示例标注)
- **工作量**:M  **验收**:示例 agent 标注依赖后,关系图自动出现对应边

## P1 — 完整性

### 4. 文件树端点 + 详情页 files 标签
- **问题**:`buildFileTree`+`FileTreeNode` 已实现但无 API 暴露;agent 详情页 files 标签是写死的 AGENTS.md/SKILL.md 占位。
- **范围**:
  - `GET /api/files?path=...&tree=1` 返回 `buildFileTree(dirPath)` 结果
  - 详情页 files 标签渲染真实文件树(可展开),点击文件预览内容
  - 复用 `formatFileSize`
- **涉及**:`src/app/api/files/route.ts`、`src/app/agents/[id]/page.tsx`、新组件 `FileTree`
- **工作量**:M  **验收**:详情页 files 标签显示 agent 目录的真实文件树

### 5. SWR 迁移(顺带清掉 set-state-in-effect 的 disable)
- **问题**:SWR 已装但全没用;数据加载是手写 `useEffect+fetch+loading`,且 agents/[id]、settings 因本地 useState 触发 `set-state-in-effect` 而加了 eslint-disable。
- **范围**:
  - agents 列表/看板/图谱:`useSWR('/api/agents')`,去掉手写 loadAgents/loading
  - settings:`useSWR('/api/workspace')` + 乐观 `mutate` 编辑
  - agents/[id]:`useSWR('/api/agents/[id]')` + 本地编辑缓冲(用 SWR key 变化触发重取,编辑缓冲用 `edited ?? data` 派生,消除 disable)
  - CardDetail:`useSWR` 取文件内容
- **涉及**:`src/app/{agents,board,graph,settings}/**`、`src/components/board/CardDetail.tsx`
- **工作量**:L  **收益**:代码更少、缓存/重新验证、移除 2 处 eslint-disable  **验收**:e2e 全绿且无 set-state-in-effect disable

### 6. 全文搜索
- **问题**:目前只能按 name/description 过滤,搜不到正文内容。
- **范围**:搜索框增加"搜正文"开关;后端 `/api/agents?q=...&full=1` 在 markdown 正文里匹配(本地扫描,可接受)。
- **涉及**:`src/app/api/agents/route.ts`、`src/app/{agents,board}/page.tsx`
- **工作量**:S  **验收**:搜正文关键词能命中
